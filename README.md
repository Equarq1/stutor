# Stutor

Веб-платформа для поиска репетиторов среди студентов КФУ. Студенты публикуют объявления о помощи с учёбой (ДЗ, семестровые, курсовые, подготовка к сессии), а другие студенты откликаются на них. Контакты репетитора и ученика открываются только после того, как заявка принята.

## Возможности

**Пользователи**
- Регистрация только с почтой КФУ (`@kpfu.ru` или `@stud.kpfu.ru`), выбор города, института, курса и группы
- Вход/выход, пароли хранятся в виде BCrypt-хэшей
- Профиль: «О себе», контакты, аватар; публичный профиль других пользователей
- Заблокированные пользователи автоматически выкидываются из сессии

**Объявления**
- Создание, редактирование, закрытие/открытие и удаление своих объявлений
- Категория, формат (`ONLINE`, `OFFLINE`, `HYBRID`, `BOTH`), цена, несколько дисциплин (с фильтром по институту и курсу), вложение (до 10 МБ)
- Лента всех активных объявлений, последние 3 объявления на главной

**Заявки и отзывы**
- Отклик на объявление с выбором дисциплины, сообщением и файлом (например, домашкой)
- Входящие и исходящие заявки; репетитор принимает или отклоняет
- После принятия заявки стороны видят контакты друг друга
- Ученик может оставить отзыв (оценка 1–5) по принятой заявке, у репетитора считается средний рейтинг

**Файлы**
- Хранятся на диске, метаданные в БД
- Доступ проверяется: файл может скачать только автор/участник заявки или администратор (аватары и вложения объявлений доступны авторизованным пользователям)

**Админ-панель** (`/admin/*`, только роль `ADMIN`)
- Пользователи (блокировка/разблокировка), объявления, отзывы (удаление)
- Справочники: города, категории, предметы

## Технологии

| Слой | Стек |
|------|------|
| Язык | Java 21 |
| Веб | Jakarta Servlet 6.1, JSP, JSTL, custom tags |
| Доступ к данным | чистый JDBC (`DriverManagerDataSource` из spring-jdbc) |
| БД | PostgreSQL |
| Безопасность | spring-security-crypto (BCrypt), фильтры `AuthFilter` / `AdminFilter` |
| JSON | Jackson |
| Прочее | Lombok, jQuery (AJAX-подгрузка групп и предметов) |
| Сборка | Maven (WAR) |

Архитектура: `servlet → service → repository (JDBC)`. Зависимости собираются вручную в `CustomServletContextListener` и кладутся в `ServletContext`.

## Требования

- JDK 21
- Maven 3.9+
- PostgreSQL 13+
- Контейнер сервлетов с поддержкой Jakarta Servlet 6.1 (например, **Apache Tomcat 11**)

## Запуск

### 1. Клонирование

```bash
git clone <URL-репозитория>
cd Stutor
```

### 2. База данных

Создайте базу и примените скрипты по порядку:

```bash
createdb stutor
psql -d stutor -f schema_stutor.sql
psql -d stutor -f data.sql
```

`data.sql` содержит стартовые данные: города, институты, группы, категории и предметы.

### 3. Настройка подключения

Скопируйте пример конфигурации и заполните его:

```bash
cp src/main/resources/db.properties.example src/main/resources/db.properties
```

Содержимое `db.properties`:

```properties
db.driver=org.postgresql.Driver
db.url=jdbc:postgresql://localhost:5432/stutor
db.username=postgres
db.password=your_password
file.storage.path=/path/to/storage/
```

> ⚠️ `file.storage.path` должен **заканчиваться на разделитель** (`/` или `\\`), так как имя файла просто дописывается к пути. Директория создаётся автоматически при старте.

Файл `db.properties` добавлен в `.gitignore` и в репозиторий не попадает.

### 4. Сборка

```bash
mvn clean package
```

Результат: `target/Stutor.war`.

### 5. Деплой

Скопируйте `target/Stutor.war` в папку `webapps` Tomcat (или задеплойте через IDE) и запустите сервер. Приложение будет доступно по адресу:

```
http://localhost:8080/Stutor/
```

## Создание администратора

Админ в приложении не создаётся автоматически. Зарегистрируйте обычного пользователя через форму, затем повысьте его роль в БД:

```sql
UPDATE users SET role = 'ADMIN' WHERE email = 'your_email@kpfu.ru';
```

После повторного входа в шапке появится ссылка «Админка».

## Основные маршруты

| URL | Описание | Доступ |
|-----|----------|--------|
| `/home` | Главная | все |
| `/registration`, `/login`, `/logout` | Регистрация, вход, выход | гости / все |
| `/offers`, `/offer?id=` | Лента и страница объявления | авторизованные |
| `/create-offer` | Создание объявления | авторизованные |
| `/my-offers` | Мои объявления | авторизованные |
| `/offer/update`, `/offer/status`, `/offer/delete` | Управление объявлением | автор |
| `/request/create` | Отклик на объявление | авторизованные |
| `/requests?type=incoming\|outgoing` | Входящие / исходящие заявки | авторизованные |
| `/request/status` | Принять / отклонить заявку | автор объявления |
| `/review/create` | Отзыв по принятой заявке | автор заявки |
| `/profile`, `/profile/update`, `/user?id=` | Профили | авторизованные |
| `/file?id=` | Скачивание файла | по правам доступа |
| `/api/groups`, `/api/subjects` | JSON для динамических списков | все |
| `/admin/users`, `/admin/offers`, `/admin/reviews`, `/admin/cities`, `/admin/categories`, `/admin/subjects` | Админ-панель | `ADMIN` |

## Схема БД

Таблицы: `users`, `cities`, `faculties`, `study_groups`, `subjects`, `offer_categories`, `offers`, `offer_subjects`, `requests`, `reviews`, `file_info`.

Ключевые связи:
- `offers` ↔ `subjects` — многие ко многим через `offer_subjects`
- `requests` ссылается на пару `(offer_id, subject_id)`; одна заявка на предмет объявления от одного студента
- `reviews` привязаны к заявке (`request_id` уникален — один отзыв на заявку)
